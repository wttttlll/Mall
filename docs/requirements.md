# MallAgent 需求规格说明

> 适用范围：MVP（阶段 0–9）。阶段 10 为 MVP 后增量，阶段 11 为交付加固；阶段 12 的 Vue 3 用户端前端 MVP 已实现于 `frontend/`，管理后台页面尚未实现。
> 本文只记录“要什么”，不记录“怎么做”。实现细节见 `modules/` 与 [`development-plan.md`](development-plan.md)。

## 1. 产品定位

面向个人消费者（B2C）的自营电商后端，单商家、单仓库、单币种（CNY）。目标是跑通从商品展示到售后退款的完整交易闭环，并作为学习真实项目全生命周期的载体。

## 2. 角色与权限

| 角色 | 说明 | 可访问范围 |
| --- | --- | --- |
| 游客 | 未登录访问者 | 健康检查、注册、登录、OpenAPI 文档 |
| 注册用户 | 已完成注册的消费者 | 用户端接口：商品浏览、购物车、订单、支付、物流、售后、个人资料与收货地址 |
| 运营 | 后台业务人员 | 管理端：按分配的权限码访问，商品、库存相关默认只读 |
| 超级管理员 | 系统管理员 | 管理端全部权限，含用户、角色、权限分配 |

约束：

- 用户端接口当前要求登录（阶段 2 现状），未登录返回 401。
- 管理端接口必须校验具体权限码，无权限返回 403。
- 任何用户只能操作自己的数据（地址、购物车、订单、售后），越权一律拒绝。
- 运营与超级管理员属于管理侧，不参与下单交易。

### 3.1 核心用户旅程（MVP 验收对象）

1. 注册并登录，维护收货地址。
2. 浏览分类与商品，查看 SKU 规格与价格。
3. 加入购物车，调整数量与选中状态。
4. 结算预览：商品金额、优惠金额、运费、应付金额。
5. 提交订单，库存与优惠券锁定。
6. 发起模拟支付并接收回调，订单转为已支付。
7. 管理端发货，物流事件推进，用户确认收货。
8. 用户申请售后，审核通过后退款，退货退款回补库存。

未完成第 8 步之前，MVP 不算闭环。

## 4. 非功能需求

### 4.1 数据一致性

- 任何情况下不得超卖：并发下单后库存不允许为负。
- 优惠券不得超发，同一用户不得超出限领数量。
- 同一幂等键重复提交只产生一笔订单。
- 支付回调、物流事件、退款请求重复到达时只生效一次。
- 退款总额不得超过实付金额。

### 4.2 金额与时间

- 金额一律 `DECIMAL(18,2)` + `BigDecimal`，禁止浮点。
- 币种固定 CNY，不实现汇率。
- 时间 `DATETIME(3)`，应用时区 `Asia/Shanghai`，接口使用 ISO-8601。

### 4.3 安全

- 密码 BCrypt 存储，任何接口与日志不得返回或打印密码。
- 认证使用 JWT，登出后旧令牌失效。
- 敏感字段（手机号、地址、支付凭据）在日志中不得完整输出。
- 密钥与数据库凭据通过环境变量注入，仓库只保留 `.env.example`。

### 4.4 接口与文档

- 基础路径 `/api/v1`，管理端 `/api/v1/admin/**`。
- 统一响应体，`code = 0` 表示成功；HTTP 状态码保留语义。
- 分页参数 `pageNum` / `pageSize`，`pageSize` 上限 100。
- 所有接口提供 OpenAPI 注解，文档可访问且与实现一致。

### 4.5 可运维性

- 每个请求可追踪：`traceId` 贯穿响应与日志。
- 表结构变更全部通过 Flyway，空库可从 `V1` 顺序执行成功。
- 依赖服务（MySQL、Redis、RabbitMQ）健康状态可查询。
- 本地环境可通过 Docker Compose 一键启动。

### 4.6 性能

- 列表查询必须有索引支撑，禁止无索引大范围扫描。
- 商品分类树与商品详情走缓存，缓存不可用时降级查库；列表查询以索引和分页控制成本。
- 本期不设定 QPS 指标，不做压测；并发正确性优先于吞吐。

## 5. 明确的非目标

以下内容当前不做，也不预埋代码：

| 类别 | 非目标 |
| --- | --- |

| 架构 | 微服务、注册中心、API 网关、分布式事务 |
| 测试 | Testcontainers（当前使用 Docker Compose 提供基础设施） |

## 6. 需求变更规则

- 范围或阶段顺序变化，先更新 [`development-plan.md`](development-plan.md)，再更新本文与索引。
- 新增核心业务设计（状态机、事务边界、幂等方案）必须先出方案并由技术负责人确认。
- 不因“以后可能用到”而扩大当期范围。
- 已验收阶段的功能变更视为新需求，需要补充对应测试与迁移脚本。
